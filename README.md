# Gitchk: a command-line tool to manage multiple git repos

This tool has two main features

- display the status of multiple git repos such as branch, modification, commit message side by side
- (batch) delegate git commands/aliases and shell commands on repos from any working directory

![gitchk screenshot](https://github.com/nosarthur/gitchk/raw/master/doc/screenshot.png)

In this screenshot, the `gitchk ll` command displays the status of all repos.
The `gitchk remote dotfiles` command translates to `git remote -v`
for the `dotfiles` repo, even though we are not in the repo.
The `gitchk fetch` command fetches from all repos and two of them have updates.
To see the pre-defined commands, run `gitchk -h` or take a look at
[cmds.json](https://github.com/nosarthur/gitchk/blob/master/gitchk/cmds.json).
To add your own commands, see the [customization section](#custom).
To run arbitrary `git` command, see the [superman mode section](#superman).
To run arbitrary shell command, see the [shell mode section](#shell).

** Make sure to `gitchk add` your repos first!


The branch color distinguishes 5 situations between local and remote branches:

| color  | meaning                                  |
| ------ | ---------------------------------------- |
| white  | local has no remote                      |
| green  | local is the same as remote              |
| red    | local has diverged from remote           |
| purple | local is ahead of remote (good for push) |
| yellow | local is behind remote (good for merge)  |

The choice of purple for ahead and yellow for behind is motivated by
[blueshift](https://en.wikipedia.org/wiki/Blueshift) and [redshift](https://en.wikipedia.org/wiki/Redshift),
using green as baseline.
You can change the color scheme using the `gitchk color` command.
See the [customization section](#custom).

The additional status symbols denote

| symbol | meaning                 |
| ------ | ----------------------- |
| `+`    | staged changes          |
| `*`    | unstaged changes        |
| `?`    | untracked files/folders |
| `$`    | stashed contents        |

The bookkeeping sub-commands are

- `gitchk add <repo-path(s)> [-g <groupname>]`: add repo(s) to `gitchk`, optionally into an existing group
- `gitchk add -a <repo-parent-path(s)>`: add repo(s) in <repo-parent-path(s)> recursively
  and automatically generate hierarchical groups. See the [customization section](#custom) for more details.
- `gitchk add -b <bare-repo-path(s)>`: add bare repo(s) to `gitchk`. See the [customization section](#custom) for more details on setting custom worktree.
- `gitchk add -r <repo-parent-path(s)>`: add repo(s) in <repo-parent-path(s)> recursively
- `gitchk clear`: remove all groups and repos
- `gitchk clone <URL>`: clone repo from `URL` at current working directory
- `gitchk clone <URL> -C <directory>`: change to `directory` and then clone repo
- `gitchk clone -f <config-file>`: clone repos in `config-file` (generated by `gitchk freeze`) to current directory.
- `gitchk clone -p -f <config-file>`: clone repos in `config-file` to prescribed paths.
- `gitchk context`: context sub-command
  - `gitchk context`: show current context
  - `gitchk context <group-name>`: set context to `group-name`, all operations then only apply to repos in this group
  - `gitchk context auto`: set context automatically according to the current working directory
  - `gitchk context none`: remove context
- `gitchk color`: color sub-command
  - `gitchk color [ll]`: Show available colors and the current coloring scheme
  - `gitchk color reset`: Reset to the default coloring scheme
  - `gitchk color set <situation> <color>`: Use the specified color for the local-remote situation
- `gitchk flags`: flags sub-command
  - `gitchk flags set <repo-name> <flags>`: add custom `flags` to repo
  - `gitchk flags [ll]`: display repos with custom flags
- `gitchk freeze`: print information of all repos such as URL, name, and path. Use with
  `gitchk clone`.
- `gitchk group`: group sub-command
  - `gitchk group add <repo-name(s)> -n <group-name>`: add repo(s) to a new or existing group
  - `gitchk group [ll]`: display existing groups with repos
  - `gitchk group ls`: display existing group names
  - `gitchk group rename <group-name> <new-name>`: change group name
  - `gitchk group rm <group-name(s)>`: delete group(s)
  - `gitchk group rmrepo <repo-name(s)> -n <group-name>`: remove repo(s) from existing group
- `gitchk info`: info sub-command
  - `gitchk info [ll]`: display the used and unused information items
  - `gitchk info add <info-item>`: enable information item
  - `gitchk info rm <info-item>`: disable information item
- `gitchk ll`: display the status of all repos
- `gitchk ll <group-name>`: display the status of repos in a group
- `gitchk ll -g`: display the repo summaries by groups
- `gitchk ls`: display the names of all repos
- `gitchk ls <repo-name>`: display the absolute path of one repo
- `gitchk rename <repo-name> <new-name>`: rename a repo
- `gitchk rm <repo-name(s)>`: remove repo(s) from `gitchk` (won't remove files on disk)
- `gitchk -v`: display gitchk version

The `git` delegating sub-commands are of two formats

- `gitchk <sub-command> [repo-name(s) or group-name(s)]`:
  optional repo or group input, and **no input means all repos**.
- `gitchk <sub-command> <repo-name(s) or groups-name(s)>`:
  required repo name(s) or group name(s) input

They translate to `git <sub-command>` for the corresponding repos.
By default, only `fetch` and `pull` take optional input. In other words,
`gitchk fetch` and `gitchk pull` apply to all repos.
To see the pre-defined sub-commands, run `gitchk -h` or take a look at
[cmds.json](https://github.com/nosarthur/gitchk/blob/master/gitchk/cmds.json).
To add your own sub-commands or override the default behaviors, see the [customization section](#custom).
To run arbitrary `git` command, see the [superman mode section](#superman).

If more than one repos are specified, the `git` command runs asynchronously,
with the exception of `log`, `difftool` and `mergetool`,
which require non-trivial user input.

Repo configuration global is saved in `$XDG_CONFIG_HOME/gitchk/repos.csv`
(most likely `~/.config/gitchk/repos.csv`) or if you prefered at project configuration add environment variable `gitchk_PROJECT_HOME`.

## Installation

To install the latest version, run

```
pip3 install -U gitchk
```

If you prefer development mode, download the source code and run

```
pip3 install -e <gitchk-source-folder>
```

In either case, calling `gitchk` in terminal may not work,
then put the following line in the `.bashrc` file.

```
alias gitchk="python3 -m gitchk"
```

Alternatively, you can install with [uv](https://github.com/astral-sh/uv)

```
uv tool install gitchk
```

Or with `pipx`

```
pipx install gitchk
```

Windows users may need to enable the ANSI escape sequence in terminal for
the branch color to work.
See [this stackoverflow post](https://stackoverflow.com/questions/51680709/colored-text-output-in-powershell-console-using-ansi-vt100-codes) for details.

Now you are ready to `gitchk add` your repos!

## Auto-completion

You can download the generated auto-completion file in the following locations for your specific shell. Alternatively, if you have installed `argcomplete` on your system, you can also directly run `eval "$(register-python-argcomplete gitchk -s SHELL)"` (e.g. `SHELL` as `bash`/`zsh`) in your dotfile.

### Bash

Download [.gitchk-completion.bash](https://github.com/nosarthur/gitchk/blob/master/auto-completion/bash/.gitchk-completion.bash) and source it in shell.

### Zsh

There are 2 options :

- [.gitchk-completion.zsh](https://github.com/nosarthur/gitchk/tree/master/auto-completion/zsh/.gitchk-completion.zsh). Use the help of gitchk command to display options. It uses the bash completion system for zsh.
  Add `autoload -U +X bashcompinit && bashcompinit` in .zshrc and source the zsh file
- [\_gitchk](https://github.com/nosarthur/gitchk/blob/master/auto-completion/zsh/_gitchk).
  Completion more Zsh style. Copy it in a folder and add this folder path in `FPATH` variable. This completion file doesn't take account to command from cmds.json

### Fish

Download [gitchk.fish](https://github.com/nosarthur/gitchk/blob/master/auto-completion/fish/gitchk.fish) and place it in `~/.config/fish/completions/`

## <a name='superman'></a> Superman mode

The superman mode delegates any `git` command or alias.
Usage:

```
gitchk super [repo-name(s) or group-name(s)] <any-git-command-with-or-without-options>
```

Here `repo-name(s)` or `group-name(s)` are optional, and their absence means all repos.
For example,

- `gitchk super checkout master` puts all repos on the master branch
- `gitchk super frontend-repo backend-repo commit -am 'implement a new feature'`
  executes `git commit -am 'implement a new feature'` for `frontend-repo` and `backend-repo`

## <a name='shell'></a> Shell mode

The shell mode delegates any shell command.
Usage:

```
gitchk shell [repo-name(s) or group-name(s)] <any-shell-command>
```

Here `repo-name(s)` or `group-name(s)` are optional, and their absence means all repos.
For example,

- `gitchk shell ll` lists contents for all repos
- `gitchk shell repo1 repo2 mkdir docs` create a new directory `docs` in `repo1` and `repo2`
- `gitchk shell "git describe --abbrev=0 --tags | xargs git checkout"`: check out the latest tag for all repos

## <a name='custom'></a> Customization

### define repo group and context

When the project contains several independent but related repos,
we can define a group and execute `gitchk` command on this group.
For example,

```
gitchk group add repo1 repo2 -n my-group
gitchk ll my-group
gitchk pull my-group
```

To save more typing, one can set a group as context, then any `gitchk` command
is scoped to the group

```
gitchk context my-group
gitchk ll
gitchk pull
```

The most useful context maybe `auto`.
In this mode, the context is automatically determined from the
current working directory (CWD): the context is the group whose member repo's
path contains CWD. To set it, run

```
gitchk context auto
```

To remove the context, run

```
gitchk context none
```

It is also possible to recursively add repos within a directory and
generate hierarchical groups automatically. For example, running

```
gitchk add -a src
```

on the following folder structure

```
src
├── project1
│   ├── repo1
│   └── repo2
├── repo3
├── project2
│   ├── repo4
│   └── repo5
└── repo6
```

gives rise to 3 groups:

```
src:repo1,repo2,repo3,repo4,repo5,repo6
src-project1:repo1,repo2
src-project2:repo4,repo5
```

### add user-defined sub-command using json file

Custom delegating sub-commands can be defined in `$XDG_CONFIG_HOME/gitchk/cmds.json`
(most likely `~/.config/gitchk/cmds.json`)
And they shadow the default ones if name collisions exist.

Default delegating sub-commands are defined in
[cmds.json](https://github.com/nosarthur/gitchk/blob/master/gitchk/cmds.json).
For example, `gitchk stat <repo-name(s)>` is registered as

```json
"stat":{
  "cmd": "git diff --stat",
  "help": "show edit statistics"
}
```

which executes `git diff --stat` for the specified repo(s).

To disable asynchronous execution, set `disable_async` to be `true`.
See the `difftool` example:

```json
"difftool":{
  "cmd": "git difftool",
  "disable_async": true,
  "help": "show differences using a tool"
}
```

If you want a custom command to behave like `gitchk fetch`, i.e., to apply to all
repos when no repo is specified, set `allow_all` to be `true`.
For example, the following snippet creates a new command
`gitchk comaster [repo-name(s)]` with optional repo name input.

```json
"comaster":{
  "cmd": "checkout master",
  "allow_all": true,
  "help": "checkout the master branch"
}
```

Any command that runs in the [superman mode](#superman) mode or the
[shell mode](#shell) can be defined in this json format.
For example, the following command runs in shell mode and fetches only the
current branch from upstream.

```json
"fetchcrt":{
  "cmd": "git rev-parse --abbrev-ref HEAD | xargs git fetch --prune upstream",
  "allow_all": true,
  "shell": true,
  "help": "fetch current branch only"
}
```

Git aliases can also be used in this json file to define custom commands. For example,
this alias checks out the default branch (usually `main` or `master`)

```
[alias]
    cod = "!f() { git checkout \"$(git symbolic-ref refs/remotes/origin/HEAD | sed 's@^refs/remotes/origin/@@')\"; }; f"
```

Then we can turn it into a gitchk command as

```
{
  "cod": {
    "cmd": "git cod",
    "allow_all": true,
    "help": "check out default branch"
  }
}
```

### customize the local/remote relationship coloring displayed by the `gitchk ll` command

You can see the default color scheme and the available colors via `gitchk color`.
To change the color coding, use `gitchk color set <situation> <color>`.
The configuration is saved in `$XDG_CONFIG_HOME/gitchk/color.csv`.

### customize information displayed by the `gitchk ll` command

You can customize the information displayed by `gitchk ll`.
The used and unused information items are shown with `gitchk info`, and the
configuration is saved in `$XDG_CONFIG_HOME/gitchk/info.csv`.

For example, the default setting corresponds to

```csv
branch,commit_msg,commit_time
```

Here `branch` includes both branch name and status.
The status symbols are similar to the ones used in [spaceship-prompt](https://spaceship-prompt.sh/sections/git/#Git-status-git_status).

To customize these symbols, add a file in `$XDG_CONFIG_HOME/gitchk/symbols.csv`.
The default settings corresponds to

```csv
dirty,staged,untracked,stashed,local_ahead,remote_ahead,diverged,in_sync,no_remote
*,+,?,$,↑,↓,⇕,,∅
```

Only the symbols to be overridden need to be defined.
You can search unicode symbols [here](https://www.compart.com/en/unicode/).

### customize git command flags

One can set custom flags to run `git` commands. For example, with

```
gitchk flags set my-repo --git-dir=`gitchk ls dotfiles` --work-tree=$HOME
```

any `git` command/alias triggered from `gitchk` on `dotfiles` will use these flags.
Note that the flags are applied immediately after `git`. For example,
`gitchk st dotfiles` translates to

```
git --git-dir=$HOME/somefolder --work-tree=$HOME status
```

running from the `dotfiles` directory.

This feature was originally added to deal with
[bare repo dotfiles](https://www.atlassian.com/git/tutorials/dotfiles).

## Requirements

gitchk requires Python 3.6 or higher, due to the use of
[f-string](https://www.python.org/dev/peps/pep-0498/)
and [asyncio module](https://docs.python.org/3.6/library/asyncio.html).

Under the hood, gitchk uses `subprocess` to run git commands/aliases.
Thus the installed git version may matter.
I have git `1.8.3.1`, `2.17.2`, and `2.20.1` on my machines, and
their results agree.
